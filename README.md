# luci-app-wol-autowake

**远程连接自动唤醒** —— 当有人从外部连接某台设备的端口时，如果它不在线，路由器自动发送 WOL 魔术包把它叫起来。

带完整 LuCI 图形界面，设备数量不限，按「外部端口」区分设备。
**端口转发和防火墙规则全部自动生成**，你只需要在网页上填一张表。

---

## 它解决什么

```
你人在外面，想连家里的台式机
        ↓
手机点「远程桌面」→ 连 mypc.example.com:21389
        ↓
台式机在睡眠，连不上
        ↓
路由器看到这次连接尝试
        ↓
自动发魔术包 → 台式机 20 秒后开机
        ↓
再点一次远程桌面 → 连上了
```

不用手动开 WOL 工具，不用记得先叫醒再连。

## 安装

### 系统是 apk（iStoreOS / OpenWrt 24.10+）

```sh
# 在电脑上执行
scp luci-app-wol-autowake-1.0.0.tar.gz root@192.168.1.1:/tmp/

# 登录路由器执行
tar -xzf /tmp/luci-app-wol-autowake-1.0.0.tar.gz -C /tmp
sh /tmp/luci-app-wol-autowake/install.sh
```

### 系统是 opkg（OpenWrt 23.05 及更早）

```sh
opkg install luci-app-wol-autowake_1.0.0-1_all.ipk
```

安装脚本会自动装依赖 `etherwake`、启用服务、清理 LuCI 缓存。

装完打开 **服务 → 自动唤醒**。

## ⚠️ 开工前：先把电脑的「网络唤醒」配好

**这一步不做，插件配得再对也叫不醒电脑。**

### ① BIOS / UEFI

进 BIOS，找到并**开启**下面任意一项（不同主板叫法不同）：

```
Wake on LAN / WOL / Power On By PCI-E / Power On By PCI
Resume By LAN / Wake Up On LAN / ErP 关闭（ErP 开着会切断待机供电）
```

> 关键：**ErP / EuP 必须关闭**，否则关机后网卡没有供电，魔术包收不到。

### ② Windows 网卡设置

```
设备管理器 → 网络适配器 → 你的有线网卡 → 右键「属性」
  → 「电源管理」标签
      ☑ 允许计算机关闭此设备以节约电源
      ☑ 允许此设备唤醒计算机
      ☑ 只允许幻数据包唤醒计算机   ← 建议勾上
  → 「高级」标签
      关机 网络唤醒 / Wake on Magic Packet  → 启用
      魔术包唤醒 / Wake on Pattern Match    → 启用
```

### ③ 关掉「快速启动」

Windows 的**快速启动（Fast Startup）会让「关机」变成休眠**，此时网卡掉电，WOL 无效。

```
控制面板 → 电源选项 → 选择电源按钮的功能
  → 更改当前不可用的设置
  → 取消勾选「启用快速启动」
```

### ④ 有线网卡

**WOL 基本只支持有线网卡。** 无线网卡唤醒支持很差，不要指望。

## 使用：添加第一台设备

### 第 1 步：打开界面

**服务 → 自动唤醒**，默认停在「设备」页。

页面顶部会显示服务状态，正常时是绿色的 **● 就绪**。

### 第 2 步：点「添加」

设备列表下面的蓝色 **添加** 按钮。

### 第 3 步：填表

| 字段 | 填什么 | 说明 |
|---|---|---|
| **启用** | ✅ 勾上 | 不勾就不参与自动唤醒 |
| **名称** | `我的台式机` | 只用来显示，随便填 |
| **外部端口** | `21389` | **从外面连过来的那个端口**，用来识别是哪台设备 |
| **目标端口** | `21389` | IPv4 转发到内网的目标端口。留空 = 与外部端口相同 |
| **内网 IP** | `192.168.1.10` | 这台设备在局域网里的地址 |
| **MAC 地址** | `aa:bb:cc:dd:ee:ff` | **必填**，魔术包就是发到这个 MAC |
| **转发协议** | `TCP` | 远程桌面选 TCP 就够 |
| **创建 IPv6 放行** | 看需要 | 勾上会额外生成一条 IPv6 放行规则 |

点 **保存**。

> 「外部端口」和「目标端口」的区别，以及 IPv6 下怎么处理，见下面
> [**安全性：把端口换掉**](#安全性把端口换掉)。

### 就完成了

保存后插件会自动做完这些事：

- ✅ 生成 **IPv4 端口转发**规则（外部端口 → 内网 IP:目标端口）
- ✅ 生成 **防火墙日志规则**（用来捕获连接尝试）
- ✅ 勾了 IPv6 的话，额外生成 **IPv6 放行**规则
- ✅ 重载防火墙，**不用你手动去配任何转发**

设备列表里对应那台机器的 **IPv4 端口转发** / **IPv6 放行** 两列会显示勾选框，
点一下就能临时关掉某一条，不用删设备。

## 设备列表怎么看

| 列 | 含义 |
|---|---|
| **启用** | 这台设备是否参与自动唤醒 |
| **名称** | 你填的名字 |
| **外部端口** | 从外面连的端口 |
| **目标端口** | 转发到内网的目标端口 |
| **在线** | 实时状态（绿色=在线） |
| **IPv4 端口转发** | 勾选 = 这条 DNAT 规则已启用 |
| **IPv6 放行** | 勾选 = 这条 IPv6 放行规则已启用 |
| **操作** | 唤醒 / 编辑 / 删除 |

> 「在线」「IPv4 端口转发」「IPv6 放行」都是实时状态，点勾选框立刻生效。

## 设置说明

**设置** 标签页里的项目，一般装完就不用动了。常用的几个：

| 设置 | 默认 | 什么时候改 |
|---|---|---|
| **每设备节流（秒）** | `60` | 同一设备这段时间内只唤醒一次。嫌唤醒太频繁可以调大 |
| **忽略国外 IP** | 关 | **建议打开**。打开后只有中国大陆来源才唤醒，国外来源只记日志 |
| **忽略 IPv6 来源** | 开 | IPv6 段数据不全，扫描器常拿 IPv6 探测，建议保持开启 |
| **内网走公网也能触发** | 关 | 在家用「公网地址」访问设备时也想触发唤醒，就打开 |
| **使用国内扫描器预设黑名单** | 开 | 内置 18 段常见扫描网段。注意：**如果你自己用云主机远程，可能会被误挡** |
| **白名单** | 空 | 填进去的 IP **无条件唤醒**，优先级最高 |
| **手动黑名单** | 空 | 填进去的 IP **一律不唤醒** |
| **启用定期清理** | 开 | 日志超过阈值自动截断，防止 flash 被写满 |

过滤优先级：**白名单 → 黑名单 → 国内 IP 判断 → 节流 → 在线判断 → 唤醒**

## 安全性：把端口换掉

**默认端口 3389 是全网扫描最密集的端口之一。** 只要你把远程桌面暴露到公网，
就会持续收到爆破尝试 —— 即使有「忽略国外 IP + 扫描器黑名单」挡着，日志也会被刷爆。

**建议一开始就不要用 3389。**

### IPv4 情况

IPv4 走的是 **NAT 端口转发**，路由器可以把「外部端口」翻译成任意「目标端口」。
**但只改外部端口是假安全** —— 内网那台机器还是监听 3389，一旦有人在局域网内
扫到就直接连上了。

所以 **外部端口和目标端口都要改**，并且 **设备自身的服务端口也要一起改**：

| 步骤 | 做什么 |
|---|---|
| ① 改设备监听端口 | 例如把 Windows 远程桌面从 3389 改成 **21389**（见下方命令） |
| ② 插件里填 | **外部端口** `21389`、**目标端口** `21389` |
| ③ 结果 | 外面连 `mypc.example.com:21389` → 转发到 `192.168.1.10:21389` |

**改 Windows 远程桌面端口**（管理员 PowerShell）：

```powershell
# 改端口（这里改成 21389）
Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp' -Name PortNumber -Value 21389

# 防火墙放行新端口
New-NetFirewallRule -DisplayName "RDP 21389" -Direction Inbound -Protocol TCP -LocalPort 21389 -Action Allow

# 重启远程桌面服务生效
Restart-Service TermService -Force
```

之后连 `mypc.example.com:21389` 即可。

### IPv6 情况

**IPv6 没有 NAT，也没有端口转发。** 公网 IPv6 地址直接指向设备本身，
插件生成的只是「**放行**」规则（让流量进得来），**它不改变端口**。

所以 IPv6 下要换端口，**只能改设备自己的监听端口**，没有别的办法：

| 步骤 | 做什么 |
|---|---|
| ① 改设备监听端口 | 同上，把远程桌面改成 **21389** |
| ② 插件里填 | **外部端口** `21389`，勾选「创建 IPv6 放行」 |
| ③ 结果 | 外面连 `[2408:xxxx::1]:21389` → 直达设备 21389 |

> ⚠️ 如果你不改设备端口，只改插件里的外部端口，**IPv6 下是连不上的** ——
> 因为设备实际还在监听 3389，而插件只负责放行 21389。

### 一句话总结

| 协议 | 改哪里 | 插件里填 |
|---|---|---|
| **IPv4** | 设备端口 + 插件两个端口 | 外部 `21389` → 目标 `21389` |
| **IPv6** | **必须改设备端口** | 外部 `21389` + 勾 IPv6 放行 |

**两边都用同一个高位端口最省事** ✓

## 常见问题

**Q：设备列表里显示「在线」，但远程还是连不上？**

A：插件只管**唤醒**，不管转发是否通。先确认：

1. 端口转发规则在 **网络 → 防火墙 → 端口转发** 里存在且已启用
2. 如果改过设备端口，**端口是否真的改成功了**（`netstat -an | findstr 21389`）
3. 路由器防火墙 → 区域设置里，WAN 的 **input / forward** 是否被设成了 reject

---

**Q：点唤醒没反应，电脑不醒？**

A：按顺序查（前两条是最常见的坑）：

1. **BIOS 里 ErP / EuP 是否关闭** —— 开着的话关机后网卡没供电，魔术包收不到
2. **Windows 快速启动是否关闭** —— 开着的话「关机」实际是休眠，WOL 无效
3. 网卡「电源管理」里是否勾了「允许此设备唤醒计算机」
4. **是不是无线网卡** —— 无线唤醒支持很差，换成有线
5. MAC 地址填错 —— 在设备页点 **唤醒** 手动测一次

---

**Q：连不上时完全没有唤醒记录？**

A：按顺序查：

1. **设置 → 监听防火墙日志** 是否勾上（关掉整个自动唤醒就失效了）
2. **忽略国外 IP** 打开时，你的来源 IP 是否在中国大陆
3. **手动黑名单** 里有没有这条 IP
4. 设备页下拉到 **可疑来源 IP**，看看这次连接有没有被记录、被判定成什么

---

**Q：怎么确认 MAC 地址填对了？**

A：在设备页点 **唤醒** 按钮手动发一次。如果电脑能醒，说明 MAC 对了；
如果醒不了，先查 MAC，再查上面那两步 BIOS / 快速启动。
